## Done
1. **The engine runs headless** (`f61d2af`).
   - Workspace's Rust core (~75k lines, 360 commands) runs as `kil-engine.exe` over a named pipe, locked to the current user.
   - Tauri was replaced by a small stand-in crate (`Engine/compat/tauri`) instead of rewriting the commands: `#[tauri::command]` generates a hidden JSON entry module.
   - The old `lib.rs` (3,628 lines of windows, tray and hotkeys) became 760 lines, plus `shell.rs` (those requests now go to the browser) and `server.rs` (the pipe).
   - `resources.rs` (from Redact's predecessor) was replaced by an original `core/throttle.rs`.
2. **The browser starts the engine on demand** (`bbd627e`).
   - New `Search.Kit` (namespace `SearchKit`, UI-free, AOT-safe) with `EngineClient` and `EngineLauncher`; 8 tests, including a real-engine test.
   - Nothing starts at launch. The first call starts the engine in about 0.5 s, and it exits 15 s after the browser leaves.
   - Test worlds get their own engine, pipe and data.
   - A bench verb: `bench.ps1 --world X engine METHOD [JSON]` (test runs only).
3. **Workspace's tools open as pages in tabs** (`e0fcaea`).
   - `Tools/` builds with Vite aliases: 13 `@tauri-apps/*` modules become a shim over `chrome.webview.postMessage`.
   - Hash routing (`#/tool/<id>`), a new index page, and a one-tool route; the old app shell moved to `#/workspace`.
   - `ToolsHost` maps `https://tools.search/` to the pages, answers `host:*` calls (dialogs, fs, opener, paths), forwards the rest to the engine and broadcasts engine events. `files.search` serves local files to tool pages only.
   - Verified: the Encoders tool ran base64 in the engine from the page. A web page couldn't navigate into the tools or read a local file through `files.search`.
4. **Commands and bangs in the field** (`cc1aa40`).
   - `SearchKit.Commands`:
     - `Command` with a tier (Read / Act / AlwaysAsks) and a source (Field / Voice / Agent / Script);
     - `CommandRegistry` (fuzzy find, argument split, tier-gated run);
     - `Bangs` (20 built in, your own in `bangs.json`);
     - `FieldInput` (`!bang`, `bang!` at the end, `>command`, `?ask`, `\` escape).
   - 33 tests, and a field read takes well under 0.5 ms.
   - The browser registers about 25 commands. `>light` switched the look, `funny cats !yt` offered YouTube, and `>clear history` asked first (Cancel is the default).
5. **`build.ps1`** now builds the engine (release) and the tool pages beside `Search.exe`.
   - Release sizes: `Search.exe` 15.1 MB (AOT), `kil-engine.exe` 20.2 MB (light features), tool pages 5.7 MB. The folder is 101 MB (was 75 MB).
   - Release smoke test: the engine starts from beside the exe at 12 MB working set, and the Encoders page ran in the engine. The browser was 131 MB with the tool tab open.

### Phase 1 starts: Shields logic in Search.Kit (`15e88de`)
- **`Search.Kit/Shields/` (namespace `SearchKit.Shields`), fully unit-tested, no browser code yet** — the browser side (`WebResourceRequested`, `NavigationStarting`, the per-site CSS injection) is still to come; see [[Ideas/Agentic Browser]] Part 1.
- **`Params.Clean(Uri)`**: a documented, data-driven list of tracking parameters
  (`utm_*`, `fbclid`, `gclid`, `dclid`, `gbraid`/`wbraid`, `msclkid`, Mailchimp/HubSpot/Marketo/Vero/Omeda ids, `s_cid`, `rb_clickid`…), plus two **host-scoped** ones
  (`ref_src` only on twitter.com/x.com, `si` only on YouTube) where the same short
  name is a real parameter elsewhere — kept conservative on purpose.
- **`Redirects.Unwrap(Uri)`**: debounces Google's `/url?q=`, Facebook's/Instagram's
  link shims, YouTube's `/redirect`, Reddit's/Steam's/Slack's/Disqus's outbound
  shims, and `href.li` (whose target isn't even a query parameter). Only ever
  unwraps to an absolute http(s) target.
- **A filter-list engine** (ABP/EasyList syntax): `NetworkRule` + `AbpPattern`
  (domain anchors, `*`/`^`/`|`, `$third-party`/type options/`$domain=`/`$important`),
  `CosmeticRule` (`##`, `domain##`, `#@#`), `FilterParser` (skips `$redirect`/`$csp`/
  `$removeparam`/scriptlets/`#?#` procedural — **counted**, never guessed at),
  `FilterList` (`ShouldBlock`, `CssFor`, a compact binary blob via `Save`/`Load`
  that skips re-parsing), `IRegistrableDomain`/`SimpleRegistrableDomain` (a small
  guessed stand-in until FishCatcher's PSL exists), `ListSource` (EasyList/
  EasyPrivacy URLs — nothing fetches them).
- **Indexing:** `||domain^` rules go in a host dictionary; other patterns are
  indexed by their **rarest** literal token, not their longest — the first cut
  (longest token) dumped every synthetic rule sharing a common word like
  "banner" into one bucket and turned a match into a 15,000-rule scan. Picking
  the least common candidate (a two-pass frequency count) fixed it; a real list
  would hit the same trap with words like "ads" or "track".
- **Benchmarks** (in `FilterBenchmarkTests`): a synthetic 60k-rule list compiles
  in **~95 ms** (budget 1.5 s), ~28 MB retained; matching averages **~1.2 µs**
  (budget 20 µs) over a mixed hit/miss request set.
- 113 tests total in `Search.Kit.Tests` (up from 49).
- **Open:** the browser hookup (`Shield.cs`/`Curtain.cs`), list downloads +
  daily refresh + ECDSA-style integrity check, and a real PSL are all still to do.

## Shields 2.0: the first three page scripts
- **`Search/Assets/js/`**: plain JS assets, each written to work two ways —
  `require()`-able from Node (pure functions, `module.exports`) and
  self-wiring when evaluated raw in a page (no `module`, so it falls back to
  `window`/`document`). Written from scratch against public, documented CMP
  APIs and the plan in [[Ideas/Agentic Browser]] Part 1 — **no uBlock Origin
  code read or copied** (its scriptlets/resources are GPL-3.0; Search is MIT).
  None of them are wired into `PageScripts.cs`/`Shield.cs` yet — that's the
  "injected later" part, once `Shield.cs` grows a per-site script list.
  - **`youtube-shield.js`**: prunes `adPlacements`/`playerAds`/`adSlots`/
    `adBreakHeartbeatParams` (and a few siblings) out of
    `ytInitialPlayerResponse`/`ytInitialData` (via property traps installed
    before the page's own `var x = {...}` runs), `JSON.parse` results that
    look like player data, and `fetch`/`XHR` bodies from
    `/youtubei/v1/player` and `/youtubei/v1/next` — by **exact field name
    only** (a `/^ad/` prefix match would also eat `adaptiveFormats`, the
    actual video streams, and break playback). Plus cosmetic CSS for the
    masthead/in-feed/overlay ad slots. Documented as an arms race: the field
    list is what YouTube shipped today, not a permanent fix.
  - **`amp-canonical.js`**: on an AMP page (`html[amp]`/`html[⚡]`) with a
    `<link rel="canonical">` to a different http(s) URL, posts
    `{name:'shield.amp', body:{canonical}}` over
    `window.chrome.webview.postMessage` and lets the browser decide (bounded
    wait, since this runs before `<head>` exists yet on most pages).
  - **`cookie-reject.js`**: **rejects, never accepts.** Tries four CMPs with
    a stable, single-call, documented reject API first (OneTrust, Cookiebot,
    Didomi, Usercentrics); Quantcast Choice/generic TCF (`__tcfapi`),
    TrustArc and Sourcepoint don't have one consistent call across versions,
    so they fall through to a conservative button-text match (reject/
    decline/necessary-only, in English + 8 other languages, with an accept-
    phrase veto) and then a CSS fallback for whatever banner is still
    standing. Bounded by a `MutationObserver` + timeout — never an open
    loop.
  - **Tests:** `Search/Assets/js/tests/*.test.js`, `node --test` — 64 tests,
    all against synthetic fixtures (no real YouTube/CMP data), covering the
    pure prune/match/decide functions plus `init()` never throwing on a
    missing or hostile `window`.

## FishCatcher in the browser
- **Wired in** (`Search/Core/Fish.cs`; details in [[FishCatcher Port]]):
  every top-level address is checked before the engine is told
  (`Tab.Forewarn`), in `NavigationStarting`, and at the document request
  itself (`WebResourceRequested`, an empty 204 for the one just stopped).
  ~0.1 ms a check in AOT; ~0.2 ms added to a navigation.
- **High/Critical** → Search's own warning page (`TroubleKind.Scam` on
  Stage): the reasons in plain sentences, **Go back**, **Go to paypal.com**
  when the real site is known, and a quiet **Continue anyway** (that host,
  until quit). **Elevated** → a quiet line at the bottom (Bars).
- **The probe** (`Search/Assets/js/fish-probe.js`, embedded): FishCatcher's
  AiTM and scam-pack collectors, posting `fish.facts`; a PayPal-branded
  password form on another host, a fake "call 1-888" lock screen and a
  recovery-phrase request were each covered. 17 new `node --test` tests (81 in
  all), including parity with the extension's matchers over the golden texts.
- **Settings › Privacy:** "Warn about scam and phishing sites" (on) and
  "Daily list of reported scam sites" (off; the feed is a download).
  Turned on in a test world, the signed feed downloaded, verified and applied
  (392,611 sites) into `Search (world)\FishCatcher`.
- **Verified** in the Debug and Native AOT builds in test worlds: opening
  `https://paypa1-secure-login.com` shows the warning with **no DNS lookup**
  (none in the DNS cache); a local server mapped with `SEARCH_HOST_RULES` saw

- **Found:** `NavigationStarting` doesn't hold the request back, and

- Bench: `"fish"` in every tab description, `fish ID back|continue|real|ok`.

## Shields 2.0 in the browser
- **Blocking (spike option B, D28):** one `*` request filter per tab and
  `Shield.Ward` deciding each request against `SearchKit.Shields.FilterList`
  (or the built-in 44 domains). The page's own document is never refused; a
  frame's document the list would refuse waits one UI turn in case it is the
  page itself. Off switches the filter off, so nothing crosses over.
- **Lists (`ShieldLists.cs`), opt-in:** "Full ad and tracker lists" in
  Settings › Privacy downloads EasyList + EasyPrivacy from easylist.to (ETag /
  If-Modified-Since, checked daily), validates them, compiles, keeps
  `Shields\lists.bin` (3.6 MB, loads in ~35 ms, 2 s after launch on a low-
  priority thread). 136,103 rules today. Fails open to the built-in list.
- **Kit (`4809ad0`):** 93k of 110k network rules are plain `||domain^`, now a
  name set: memory 34 → 18 MB, a match 3.5 → 2 µs. Cosmetics split into
  `GenericCss` (one sheet for every site, 100 selectors a rule, unsafe
  selectors refused) and `SiteCss(host)` (own rules + the generic ones some
  exception depends on); `$generichide` understood. 19 new tests (174).
- **Cosmetics in the page:** the shared sheet goes in once per tab as a
  document-created script that adopts a `CSSStyleSheet` (no element needed,
  not subject to the page's CSP); the per-site sheet is swapped in at each
  navigation (new added before old removed, host-checked in the page, and
  re-run at `ContentLoading` for a page that beat it). Paused sites,
  `$generichide` sites and `*.search` get none.
- **Addresses:** `Tab.Tidy` cleans what Search navigates to (typed,
  bookmarks, bench); `NavigationStarting` replaces an engine navigation with a
  clean one (new documents only; tags only across sites; unwrapping always;
  a site that bounces back gets its way the second time). Copy Address copies
  the clean one. Never tidies into `*.search`.
- **Page scripts:** youtube-shield.js (all frames, youtube only), cookie-
  reject.js (all frames; frames only when they are a consent dialog),
  amp-canonical.js → `shield.amp` → `location.replace` to the canonical,
  cleaned, once per AMP page. All step aside on paused sites (by the top
  page's site, via `ancestorOrigins`).
- **cookie-reject.js hardened (`a6c338d`):** a whole-text match inside a
  consent container only (it would have clicked "Senate to reject the bill"),
  CMP APIs only while consent is pending (it would have overridden your own
  earlier "accept" on every visit), a throttled observer, textContent. 89 node tests.
- **Settings › Privacy:** Block ads and trackers (on), Full ad and tracker
  lists (off, download), Remove tracking from links (on), Dismiss cookie
  banners (on), Block on <site>.
- **Verified in test worlds** (bench): theverge's ad scripts (gpt.js,
  apstag, prebid, doubleverify…) all status 0; utm/fbclid off typed and
  clicked addresses; google.com/url?q= unwrapped and out of history; same-site
  tags kept; a local AMP page replaced by its clean canonical; a fake OneTrust
  banner's "Reject all" clicked while a headline and a lone "Reject" button
  weren't; YouTube's player response without `adPlacements`/`playerAds`,
  formats intact.
- **Measured (Native AOT, warm cache, median of 3):**

  | | off | built-in | lists |
  |---|---|---|---|
  | example.com DCL | 15 ms | 16 ms | 21 ms |
  | Wikipedia DCL | 153 ms | 164 ms | 165 ms |
  | theverge DCL | 299 ms | 325 ms | 302 ms |
  | theverge load event | 6,169 ms | 717 ms | 691 ms |
  | theverge requests (loaded) | 339 (221) | 241 (159) | 175 (142) |
  | theverge handler time | — | 2.7 ms / 256 req | 3.0 ms / 183 req |

  The lists cost ~5 ms on a tiny page (parsing the 200 KB generic sheet;
  `replaceSync` alone is ~1.3 ms) and about +30 MB in Search.exe; heavy pages
  finish far sooner. Wikipedia ±15 ms is noise.
