# 2026-09-26: Phase 2 (the universal field)

Back to [[README]] · Plan: [[Master Plan]] · Protocol: [[Engine Protocol]], [[Engine Commands]]

## Done

The universal field is built and wired into the browser. Four agents completed this phase concurrently: one built the field model and its tests in Search.Kit (145 new tests, all passing); one fixed critical bugs in the Engine's pipe server and wired the search-services command; one integrated the field into the browser and verified file/app/answer rows work; one added clipboard history on by default with a Ctrl+Shift+V popup.

1. **Search.Kit/Field (`SearchKit.Field` namespace)** (`1e2cc7e` merge).
   - Query classification: `FieldQuery.Read(typed)` returns the query kind (Address, Words, Calculation, Conversion, Color, Hash, Encode, Format, Command, Bang, Ask) and scope (All, Files, Apps, Clipboard, Tabs, History).
   - Row deduplication and merging: `FieldBoard` keeps late engine results from moving the user's pick, with a 200-trial randomized test.
   - Field model: `FieldModel` runs each keystroke with per-source debounce and cancellation via `CancellationToken`.
   - Instant answers: calculator, unit conversion, encode/decode, color conversion, hashes (MD5, SHA1, SHA256), format conversion (JSON ↔ YAML/TOML/XML).
   - Clipboard history source (on by default), files (by name and contents), apps (with icons), history, bookmarks, tabs, commands, bangs, typed text (Go or search).
   - 145 new tests in `Search.Kit.Tests/Field/`, all passing. `FieldQuery` reads in 0.17 µs per call on average.

2. **Engine pipe server fixes and wiring** (`cc29438`).
   - **Critical bug:** the reconnect deadlock. After the first client left, the accept loop slept inside the same `tokio::select!` branch it polls `server.connect()` from, so the engine could not accept a second connection and then self-terminated. Fixed by moving the linger deadline into its own select branch, so `server.connect()` stays live throughout the grace period.
   - **Missing registration:** `start_search_services` was defined with `#[tauri::command]` but never added to `generate_handler!`, making it uncallable. Added it alongside other `start_*` commands.
   - **Filename search regression:** synonym expansion (e.g., "invoice" → 5 keywords) and the "3+ keywords must match half" rule broke single-word queries. Now counts only typed words (`typed_keywords`).
   - Engine tested live, headless, over the named pipe: 30 checks pass, including file index build/search/contents/preview, apps launch, instant answers, and full clipboard lifecycle with sensitive tagging.

3. **Field integrated into the browser** (`9ce44c6`, `129b3c0`, `3262750`).
   - **Search/Core/Browser.Field.cs:** mixes the browser's own rows (tabs, history, bookmarks, commands, bangs, typed) with the field model's board, with the board's top hit (an answer or first engine row) reserved as a Pending slot filled in place.
   - **Settings › Search:** folders to index, "Search inside files" (on by default), "Apps in the field" (on by default), and an index status line polling `get_file_search_status`.
   - **FileIndex:** saves `save_file_search_index_options` on folder changes, calls `start_search_services`, and builds whichever index (names or contents) hasn't been built yet. Waits 4 seconds after launch before starting, only when at least one folder is chosen.
   - **Gating:** file sources only when folders exist; app sources only when the setting is on; both skip asking if `Engine.Available` is false (engine missing or unavailable).
   - **File rows:** `FileKinds.ActionFor(extension)` maps to OpenInTab (PDF, image, text, Markdown, JSON), Play (audio, video), or OpenWithApp (everything else). Folders are revealed in Explorer. Clipboard entries map to Copy or CopyClip.
   - **Enter behavior:** a picked engine row acts immediately (files open as `file://` in tabs, apps launch, answers copy). With nothing picked, `?` and `>` commands run directly; answer queries wait 150 ms for the engine then fall back to web search; `files:/apps:/clip:` scopes open their first row or refuse if empty.
   - **Omnibox draws:** engine rows under group headings (Answers, Files, Apps, Clipboard), late rows go below the browser's rows, picked/hovered rows never move, pending slots are drawn as quiet empty rows.

4. **Clipboard history on by default** (`23ff84e`).
   - **New ClipHistory (Search/Core/ClipHistory.cs)** and **ClipPopup (Search/UI/ClipPopup.cs)**.
   - **Ctrl+Shift+V** opens a searchable popup: pinned entries first, newest below, pictures show thumbnails, secrets show only their kind ("Hidden: stripe secret key") until clicked Show. Max 30 rows on screen; type to narrow.
   - **Paste targets:** text inserts into a focused field (address bar, tab search, page textarea/input/contenteditable); pictures into pages go back on the clipboard + a Ctrl+V key event; secrets do not return to the clipboard after pasting into a field.
   - **Where Enter pastes:** decided when the popup opens — field focus, page focus (via DevTools `Input.insertText`), or clipboard-only fallback.
   - **Settings › Clipboard:** on/off (default on), keep for N days, keep pictures (on/off), pause, password-manager exclusion list with app names + a "Put back defaults" button, Clear (keeps pinned).
   - **QuietCopy (Search/Core/QuietCopy.cs):** marks a copy so Windows and clipboard managers skip it: `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory=0`, `CanUploadToCloudClipboard=0`. Used by `Browser.Copy(Login)` (passwords) and the field's Answer/CopyClip rows.
   - **Engine listener fix:** rapid OLE-delayed copies (PowerShell `.SetText`) were failing ~1–2%. Now the engine reads 60 ms after `WM_CLIPBOARDUPDATE`, not at once, via a `WM_TIMER` in `wnd_proc`. Zero failures afterward.
   - **Kit changes:** `ClipEntry`, `ClipList` in `Search.Kit/Field/ClipList.cs`; `FieldQuery` reads bare word `clipboard` as the clipboard scope.
   - **Startup:** engine starts at 3 s after launch (Browser.ctor → `StartFeatures` → UI.After(3 s)); calls `start_clipboard_listener`. `EngineClient.Connected`/`Disconnected` events allow restart on crash; first retry waits 5 s, doubling up to 300 s.

- Files and executables from indexed folders open without asking via `open_search_result_path` (ShellExecute).
- Test worlds record the real clipboard by default, and bench reports show it.
- Ambiguous calculation forms ("24/7", "9/11") are treated as sums, not searches.
- A paste can go to the tab chosen when the popup opened, even if that page has since navigated to another site.

**Low severity (6+):**
- When an answer never arrives, its reserved row is removed and browser rows shift up under the pointer.
- On a cold engine, fast typing can launch several engine processes; some UI-thread callers block while the engine starts.
- Pause state in ClipHistory can drift from the tool pages.
- Data left on disk when features are turned off.
- Popup filtering runs on the UI thread; file reads and redraw on every keystroke.
- Engine settle timer can stop recording if the listener thread exits mid-timer.
- Plus 6 more (see review section below).

**Architectural notes from the report (not bugs, but worth tracking):**
- GatedSource wraps engine sources, checking `Engine.Available` and a predicate per source.
- IndexPlan governs what gets indexed; IndexStatus reads the engine's status.
- Late rows arrive via engine events and are posted to the UI thread with a generation check.
- FieldMix.Compose merges local rows and board rows, keeping the top hit reserved.

## Decisions

**D30 · Clipboard history on by default (2026-09-26).**
- **Decision:** clipboard history is on by default in every fresh install and test world. Settings › Clipboard lets users turn it off, choose retention (1 day to 1 month), keep pictures (on/off), pause, and exclude password-manager apps.
- **Why:** the user found clipboard history "much better and useful" as the default (message at phase 2 start); it's a browsing-scale feature with sensitive tagging, and QuietCopy ensures passwords from the browser don't enter the history.
- **Secret handling:** the engine auto-tags copies via sensitive_scan (API keys, credit cards, SSNs); secrets keep a 5-minute retention regardless of the general setting. Secrets in the Ctrl+Shift+V popup show as "Hidden: {kind}" and require Show to view the text. Pasting a secret into a Search field does not return it to the clipboard (but pasting into a page does — see findings).
- **Revisit:** if the clipboard history file grows faster than expected, or if a user on metered bandwidth finds the 4 MB daily download (two filter lists) excessive even when Shields are on, offer a small-data build with lists pre-signed.

## Engine Commands

A full reference is in [[Engine Commands]] (new). The protocol is JSON-RPC over a named pipe (`search-engine[-world]`), one JSON line per request/response. Events arrive on the same connection asynchronously (a line with an `"event"` key instead of an `"id"`).

**New or revised in phase 2:**
- `start_search_services` (was broken, now callable): initializes the file-index scheduler.
- `start_filename_search_index`, `start_content_search_index`, `start_file_search_index`: build indexes. Contents are built only by an explicit call or the scheduler.
- `get_file_search_status`: returns index counts, build status, error, and diagnostics.
- `search_local_files`, `search_file_contents`: query the built indexes.
- `stop_file_search_index_watcher`: stop watching for file changes.
- `start_clipboard_listener`, `get_clipboard_history`, `pin`/`delete`/`clear`/`label` clipboard entries, `copy_clipboard_entry_to_clipboard`: clipboard lifecycle.
- `evaluate_quick_query` (returns calculator, unit conversion, systemCommand, openUrl, webSearch — field takes only calculator/unitConversion), `encode_decode`, `convert_format`: instant answers.
- `search_launch_targets`, `ensure_launcher_icon`, `launch_cached_target`: apps.
- `open_search_result_path`: open a file or folder with its associated app (ShellExecute).

## Round 4: the small items (2026-09-26)

Engine and Kit fixes addressing index state/locking, prefix search, and rule deduplication, merged s-engine2 and s-kit2 into main.

**Engine (s-engine2):** 6 fixes in search.rs and local_db.rs.
1. **State DB shared with worker processes (HIGH).** The migrate-on-startup path used `get_db`, which caches a locked handle. Worker processes then couldn't open the same database. Fixed: `search.rs` normalizes the config once and saves with `write_search_config_for_state` (write_json_shared), which doesn't cache. `local_db.rs` tracks shared opens and refuses get_db on a registered path.
2. **Prefix pass ranks 3+ typed words (MEDIUM).** Single words like "note" omit one-word entries when a page of name-matches fills. 3. **Hidden entries walked (LOW).** includeHidden walked FILE_ATTRIBUTE_HIDDEN entries. Fixed: single `index_walk(root, options)` builder with filter_entry that skips FILE_ATTRIBUTE_HIDDEN. Dot-folders still governed by include_hidden; nested root deduplication via `walked_roots`.
4. **Related-term-only rule (LOW).** Unfactored when 3+ words were typed. Fixed: `build_result_item` counts only typed_keyword_hits.
5. **Cache locks busy-waited 5 s (LOW).** Fixed: BUSY_WAIT (5 s) for get_db; CACHE_WAIT (100 ms) for ocr/vector/duplicate/perceptual caches.
6. **Excluded folders descended (LOW).** Walker returned Continue instead of Skip. Fixed: same filter_entry logic.
Default exclusions now include desktop.ini, Thumbs.db, \*/ntuser.\*, \*/~\$* on Windows.

## Round 6: the field's real search path, and the folder picker

**The three failed checks had one cause:** the field asks two engine sources,
and the fixes had only reached the file-name one.
- `sample notes budget` → memo 3.txt came from *content* search, which widened
  "notes" to "memo" with no typed-word rule. Now, with 3+ typed words, a file
  needs half of them (same-stem plurals count; related terms don't).
  `invoices budget tax` still finds `invoice budget.xlsx`.
- `notes` → notes.txt: a new ranking signal, how much of the name the typed
  words make up (notes.txt fully, notes-17.md half); path-only hits get none.
- `note` → notebook.txt: the names starting with a typed word are always read,
  from the longer indexed name words.
- Also fixed: watchers skip AppData and hidden folders (they indexed what the
  walk skipped); a nested chosen folder is walked unless the outer walk truly
  reaches it (.gitignore, hidden); `.ssh` and the like are refused in Settings;
  index workers die with their engine (a kill-on-close job); one check per
  folder in the walk.

**Found by hand on the AOT build:** Settings › Add folder did nothing. The old
`Windows.Storage.Pickers` show the dialog in an unpackaged app, then return
E_FAIL once a folder is chosen; a bare `catch { }` hid it. Every picker now
use the App SDK's own pickers (`Microsoft.Windows.Storage.Pickers`, owned by
`AppWindow.Id`, giving paths) through `Search/UI/Pick.cs`: search folders,
downloads folder, a space's folder, load an extension, import passwords, and
tool pages' open/save.

**Checked by hand on AOT** (test world, Settings clicked through): add `work`
→ indexed; add `work\.config` → accepted; `work\docs` → "Already searched";
`work\.ssh` → "Not searched: it holds keys or sign-ins"; hidden `work\Stuff` →
accepted. The field then finds zebra.json (.config), stuff.txt by its content
(hidden Stuff) and readme.txt; nothing under `build` or `.ssh`. Engine
workers exited with the app.
